## Apollo Portal（8070）未跳转登录页 —— 已定位并修复

**根因**
1. `spring.profiles.active=github,auth` 是在进程启动之后才写入 `apollo-portal/src/main/resources/application.properties`，
   运行中的实例（IDEA 调试，00:13:56 启动）仍是旧配置 → 只激活 `github`/`oracle`，落到 `DefaultAuthAutoConfiguration`，
   任何请求都不校验身份。profile 只在启动时读取，必须重启。
2. 只重启还不够：Oracle 里 `USERS`/`AUTHORITIES` 是**不加引号**的大写表，
   而 `AuthConfiguration#jdbcUserDetailsManager` 拼的是 `"Users"`/`"Authorities"`（Hibernate OracleDialect openQuote = `"`），
   JPA 实体 `UserPO`/`Authority` 也是 `@Table(name = "\"Users\"")`。大小写不匹配 → 登录时 ORA-00942。

**处理**
- Oracle（APOLLO_PORTAL schema）执行：`ALTER TABLE USERS RENAME TO "Users"` + 6 个列改名；
  `ALTER TABLE AUTHORITIES RENAME TO "Authorities"` + 3 个列改名；`DROP TRIGGER APOLLO_PORTAL_USERS_UPDATE_TIMESTAMP`
  （该触发器引用不存在的 DATACHANGE_LASTTIME 列，属无效对象）。数据保留：1 行 apollo + 1 行 ROLE_user。
- `scripts/sql/src/apolloportaldb.sql`：补上两处 `COMMENT ON TABLE APOLLO_PORTAL.USERS/AUTHORITIES` 的引号（之前会直接报错）。
- 用 8071 临时端口验证：profiles = github/oracle/auth，`/` → 302 `/signin`，apollo/admin 登录成功，错误密码 → `/signin#/error`。

**账号**：apollo / admin（库里 bcrypt 哈希已校验 = admin）。

**待办**：IDEA 里重启 8070 的 PortalApplication 才能生效。

## 禁止 apollo 账号创建应用

**为什么不能只靠配置**：`apollo` 在 PortalDB.ServerConfig 里是 `superAdmin`，
`DefaultRolePermissionService.userHasPermission` 对超级管理员直接 return true，
所以 `role.create-application.enabled=true` 这套内置开关对它无效。

**改法**（新增否决名单，优先于 superAdmin 放行）：
- `SystemRoleManagerService.hasCreateApplicationPermission(userId)` 开头加 `isCreateApplicationDenied(userId)` 判断，
  命中直接返回 false 并打 WARN 日志。
- `PortalConfig.createApplicationDeniedUsers()` 读 `role.create-application.denied-users`（默认 `apollo`，逗号分隔，置空即关闭）。
- 因为这个方法是唯一出口：
  - `AppController#create` 的 `@PreAuthorize("@userPermissionValidator.hasCreateApplicationPermission()")` → 403
  - `GET /system/role/createApplication/{userId}` → 前端 `IndexController.initCreateApplicationPermission()` 据此隐藏"创建应用"按钮

**验证**（8071 临时实例）：apollo → `{"hasCreateApplicationPermission":false}`；未列入名单的用户 → true；
`POST /apps` → 403 `AccessDeniedException/不允许访问`，日志有 "is in the create-application denied list"。

**副产物**：`mvn` 需要 `JAVA_HOME=/d/Program Files/Java/jdk-11.0.33.0.3`（环境里默认的 jdk-26 路径已失效）。

## 用户自助修改本人密码

原来只有超管能改密码（`POST /users` + `PUT /users/enabled`），没有任何自助入口。

**后端**
- 新增 `entity/vo/ChangePasswordRequest.java`（oldPassword / newPassword）。
- `SpringSecurityUserService#changePassword(username, old, new)`：校验旧密码 → 拒绝与旧密码相同 → `passwordEncoder.encode` 落库。
- `UserInfoController#changeOwnPassword` → `PUT /users/password`，**无 @PreAuthorize**（登录即可），
  用户名只从 `userInfoHolder` 会话取，请求体不含 username，天然防越权；新密码复用 `AuthUserPasswordChecker`（8~20 位、字母+数字）。
- 密码编码用 `DelegatingPasswordEncoder`：老数据是裸 `$2a$10$...`（走 defaultPasswordEncoderForMatches=BCrypt），
  新改的会写成 `{bcrypt}$2a$...`，两种都能登录。

**前端**
- `views/component/change-password-modal.html`（新）+ `UserService#changePassword` + i18n 中英文各 9 个键。
- 入口：导航栏用户下拉「修改密码」，逻辑写在 `directive.js` 的 `apollonav` link 里。
- 坑：`apollonav` 是 `replace: true`，模板必须单根节点，`ng-include` 容器要放在 `<nav>` 内部，不能并列。

**验证**（8071 临时实例，已清理）
- 旧密码错 → 400；新密码 `123` → 400 弱密码提示；正常 → 200。
- 改完新密码可登录（302 `/`），旧密码 → `#/error`。
- 普通用户（临时建 pwdtest，非超管）同样能改自己的密码 → 200。
- apollo 的密码已还原为 `admin`，测试用户已从库里删除；库里现有账号：apollo、xiongdw。

## 用户-部门多对多 + 登录选部门 + 按部门看应用

**需求**：① 管理员建用户时给用户选多个部门；② 登录页必须选部门；③ 登录后"我的应用"展示所选部门全部应用（含他人创建）。

**方案**（用户选定）：
- 部门关系：新建 `UserOrg` 关联表（Username + OrgId，多对多），非 Users 加列。
- 登录：登录表单加部门下拉，登录成功由 `ApolloAuthenticationSuccessHandler` 把 orgId 写 session。
- 展示：只显示登录所选部门的应用，首页顶部可切换部门（多部门用户）。

**后端改动**
- 新增 `entity/po/UserOrg.java`（表 `"UserOrg"`）+ `repository/UserOrgRepository.java`（findByUsername/findByOrgId/deleteByUsername）。
- `entity/po/UserPO.java` 加 `@Transient List<String> orgIds`；`entity/bo/UserInfo.java` 加 `orgIds`。
- `SpringSecurityUserService`：构造注入 UserOrgRepository；`create`/`update` 里 `saveUserOrgs`（update 先 deleteByUsername 再重存）；
  `findByUserId`/`findByUserIds`/`searchUsers` 都改用 `toUserInfoWithOrgs` 填充 orgIds。
- 新增 `component/LoginOrgHolder.java`：session 级持有当前部门 key `APOLLO_LOGIN_ORG_ID`，含 `setLoginOrgId(request, orgId)` 重载。
- 新增 `spi/springsecurity/ApolloAuthenticationSuccessHandler.java`：登录成功读 `orgId` 参数写 session，强制跳 `/`。
- `AuthConfiguration`：`SpringSecurityConfigurer` 注入 LoginOrgHolder 并 `.successHandler(...)`；`BY_PASS_URLS` 加 `/organizations`；`springSecurityUserService` bean 注入 UserOrgRepository。
- `AppController#findAppsBySelf`：优先按 `loginOrgHolder.getLoginOrgId()` 用 `appService.findByOrgId(orgId, page)` 查该部门全部应用，否则回退原角色逻辑。
- `AppRepository`/`AppService` 加 `findByOrgId(orgId, pageable)`。
- `UserInfoController`：注入 LoginOrgHolder，新增 `GET /user/current-org`（查当前部门）、`PUT /user/current-org`（切换部门，校验属于该用户 orgIds 否则 400）。

**前端改动**
- `login.html`：表单加部门下拉（name=orgId）；`LoginController.js` 注入 OrganizationService 加载部门；引入 OrganizationService.js。
- `user-manage.html`：加部门多选（select2 `#org-select`）；`UserController.js` 注入 OrganizationService，changeStatus 回显/清空 orgIds。
- `index.html`：加部门切换下拉（多部门时显示）；`IndexController.js` 加 initOrgSwitch/switchOrg，注入 OrganizationService；引入 OrganizationService.js。
- `UserService.js` 加 `getCurrentOrg`/`switchCurrentOrg`。
- i18n 中英文加 `Login.SelectDepartment`、`Index.Department`、`Index.SwitchDepartmentFailed`、`UserMange.Department`。

**关键坑**
- 登录成功处理器里 `RequestContextHolder` 可能未绑定，`LoginOrgHolder.getSession(false)` 拿不到 session → 需用 `request.getSession()` 直接从 request 拿（加了 `setLoginOrgId(request, orgId)` 重载）。
- `ServerConfig` 表实际是大写 `SERVERCONFIG`（列 KEY/VALUE 大写），organizations 值存在 DB（`[{"orgId":"TEST1","orgName":"样例部门1"},{"orgId":"TEST2","orgName":"样例部门2"}]`）。

**数据库**

- 种子数据：apollo→TEST1+TEST2，xiongdw→TEST1。
- 现有应用 `test` 属于 TEST1（owner=xiongdw），正好验证跨用户同部门可见。

## 部门下拉重复 + 部门必填（追加）

**问题**：用户管理页部门下拉展示 4 个部门（样例部门1/2 + 样例部门1(TEST1)/样例部门2(TEST2)），实际只有 2 个。
- 根因：`user-manage.html` 的 `<select>` 里 `ng-repeat` 预填 `<option>`（text=orgName），而 `UserController.js` 又 `select2({data})`（text=orgName+'(orgId)'），select2 把原 option 保留 + 追加 data → 重复成 4 个。
- 修复：去掉 `<option ng-repeat>`，select2 data 的 text 改用纯 `orgName`（不再拼 orgId）。

**新增需求**：除 `apollo` 外，其他用户添加/修改时必须选部门，否则报"请选择用户所属部门"。
- 后端 `UserInfoController#createOrUpdateUser`：`!"apollo".equals(username)` 且 `orgIds` 为空 → `BadRequestException("请选择用户所属部门")`。
- 前端 `UserController.js#createOrUpdateUser`：同样校验，`toastr.error` 提示（i18n 键 `UserMange.DepartmentRequired`）。
- **连带修复**：`UserOrgRepository#deleteByUsername` 加 `@Modifying + @Transactional`，否则 `update` 里删关联时抛 "No EntityManager with actual transaction available"（500）。

**验证**（8071 临时实例，已关闭清理）：organizations 返回 2 个；非 apollo 无部门创建/修改 → 400"请选择用户所属部门"；带部门 → 200 且部门正确更新；apollo 豁免（走弱密码校验，属正常）。测试用户 orgtest2 已清理。

## 登录必须选部门（追加）

**问题**：不选部门反而能看到应用（回退按角色查所有应用），选了部门反而看不到（应用 orgId 不匹配）。
- 根因：`ApolloAuthenticationSuccessHandler` 登录时 orgId 为空会 `clear()` 放行，`AppController#findAppsBySelf` 无 orgId 时回退"按角色查应用"。
- 修复：`ApolloAuthenticationSuccessHandler#onAuthenticationSuccess` 中 orgId 为空 → 抛 `OrgRequiredAuthenticationException`（内部静态类）→ 跳 failureUrl `signin?#/error`，强制登录必选部门。
- 前端：`login.html` form 加 `onsubmit="return validateLoginOrg()"`；`LoginController.js` 定义 `$window.validateLoginOrg`，未选部门提示 `Login.SelectDepartment`（"请选择部门"）并阻止提交。
- 注意：用户截图里 test 应用是「待分配部门TEST3」、owner=xiongkw，与本地 8070 库（test=TEST1、owner=xiongdw）不一致，说明用户看的是另一个环境的数据。"选了部门看不到"在该环境下是因应用 orgId 不在所选部门所致，非代码 bug。
